# 开发需求文档（Requirements）

## 1. 背景与问题

远端 Resilio Sync 服务器性能差，其自带 Web UI（`http://server:8888/gui/`）存在以下问题：

- 加载大量 HTML/CSS/JS 静态资源（约 2-5MB）
- 每 ~3 秒轮询 5+ 个 API 端点
- 页面经常加载不出来

项目最初是一个基于 `requests` 的命令行客户端，可完成登录、导出/导入、暂停/恢复等操作，但没有可视化的实时状态面板。

## 2. 目标

构建一个**运行在本地的轻量 Web 应用**（Flask + 浏览器），它：

- 只对远端服务器发起最少、最轻的 JSON API 调用
- 在本地渲染 UI，不加载远端 Web UI 的任何静态资源
- 大幅降低远端服务器资源消耗（目标减少 80-90% 的 API 请求量）

## 3. 功能需求

### 3.1 已确认功能范围（P0-P7）

| 编号 | 功能 | 说明 | 优先级 |
|------|------|------|--------|
| F1 | 登录 | 输入远端服务器地址、用户名、密码，验证成功后建立会话 | P0 |
| F2 | 实时同步状态仪表盘 | 文件夹列表 + 全局速度，5-10 秒轮询刷新（仅更新 DOM） | P0 |
| F3 | 节点列表 | 显示所有已连接节点信息 | P1 |
| F4 | 速度控制 | 查看/设置全局下载、上传速度限制 | P1 |
| F5 | 文件夹操作 | 单个文件夹暂停 / 恢复 / 删除 | P1 |
| F6 | 批量操作 | 暂停所有 / 恢复所有 | P2 |
| F7 | 导入导出 | CSV 导出文件夹列表 / 从 CSV 批量导入 | P2 |

### 3.2 明确非目标（本期不做）

- 不实现远端 Web UI 的完整功能复刻
- 不做多用户、权限分级
- 不引入数据库（会话状态存 Flask 客户端 cookie）
- 不部署到公网（仅限本地 localhost 使用）

## 4. 非功能需求

### 4.1 性能（核心目标）

| 指标 | 目标 |
|------|------|
| 静态资源加载 | 0（远端），全部由本地 Flask 提供 |
| 初始 API 调用数 | 仅 1 次登录 + getsyncfolders |
| 轮询频率 | 5-10 秒（可配置），默认 5 秒 |
| 每次轮询 API 数 | 1-2 个（getsyncfolders + getpeersstat 合并到 /api/status） |
| 每秒远端 API 请求 | ~0.1-0.2 次/秒（原 Web UI 约 1.67 次/秒） |

### 4.2 安全

- 服务器密码只存于本地 Flask 会话 cookie（客户端签名 cookie：base64 明文可解码 + HMAC 防篡改，并非加密），绝不写盘；登录会话永久化（30 天），关浏览器后免重填（2026-08-21）
- 密码在浏览器端提交时使用 HTTPS 传输（若 Flask 走 HTTP，仅限 localhost 且向用户说明风险）
- 远端 HTTPS 自签名证书：内置 TlsAdapter 兼容模式
- 服务器地址/密码不得出现在日志中

### 4.3 兼容性

- 远端服务器为旧版 Resilio Sync（需 TLSv1 / 弱加密兼容），复用 `TlsAdapter`（`DEFAULT@SECLEVEL=1`）
- 前端兼容现代浏览器（使用 `fetch` API），无外部 JS 依赖（除 Bootstrap 5 CDN）

## 5. 验收标准

1. `pip install -r requirements.txt` 后 `python app.py` 可启动，默认 `http://127.0.0.1:5000`
2. 浏览器登录后仪表盘实时显示所有文件夹状态、全局速度
3. 暂停/恢复单个文件夹功能生效且刷新后状态正确
4. 节点列表页面显示已连接节点
5. 速度限制设置保存后生效
6. 早期 CLI 客户端功能不受影响（回归通过，历史项）
7. 与直接访问远端 Web UI 相比，远端 API 请求量显著下降（满足 4.1 指标）

## 6. 需求变更流程

- 任何需求变更先更新本文档（标注变更日期与原因），再进入开发
- 变更影响范围超过单个阶段时，同步更新 [development-plan.md](development-plan.md)

## 7. sync-guard 集成需求（2026-08-05 新增）

将服务器端 sync-guard（OOM 配置保护 + 假死健康检查）与 sync_sched（智能分批调度，D/C/B/A 分级）整合进本地面板。项目代码见 [sync-guard/](../sync-guard/)。

### 7.1 范围

| 编号 | 需求 | 说明 | 依赖 |
|------|------|------|------|
| G1 | 面板显示调度判定 | 「调度」页 + 仪表盘分级徽标；每个文件夹显示真实名称、D/C/B/A 分级、需上传/做种/待下载对端数、当前状态与判定说明 | 无（纯面板侧，复用 sync_sched.grade） |
| G2 | 面板查看守护状态 | 「守护」页显示 OOM 重启次数(NRestarts)、最近备份时间、健康检查状态、调度模式 | 需 guard HTTP 接口 |
| G3 | 面板控制调度器 | 切换模式(off/dry/on) + 常用参数（max_running/seed_limit/run_min_stay/preheat_sec/权重） | 需 guard HTTP 接口 |
| G4 | guard HTTP 接口 | 服务器端轻量 HTTP 接口（:8890，token 认证）：GET /api/status、GET/POST /api/sched；写 env + 重启 guard 服务 | 服务器部署 |
| G5 | 安全模式 | 滑窗内 OOM 次数超过阈值（默认 600s 内 >3 次）时，直接把备份改写为全部暂停并强制回放，暂停所有文件夹打破 OOM 循环；稳定 SAFE_EXIT_QUIET 秒后自动解除 | sync_guard.py（纯服务器侧） |
| G6 | 冗余做种断开 | 做种人数（seeded=在线且完全同步的对端数）超过阈值（默认 10）的文件夹自动断开，节省内存；其他对端已覆盖内容、可用性不受影响；断开后保留文件、面板可见可手动重连 | sync_guard.py + 面板配置 |
| G7 | 仪表盘内存占用 | 仪表盘显示 rslsync 内存占用（RSS 占 cgroup 上限百分比，绿/橙/红三色），悬停显示 RSS/上限/swap/系统可用明细；数据由 guard 接口 `/api/status` 的 `mem` 字段提供（节流 30s 采样） | guard_webapi + 面板 |
| G8 | 断开文件夹定期重连 | G6 断开后定期接回复查：每 10 分钟重连 1 个，两道闸门（内存 rss/cg_max>75%、磁盘 IO 忙度>90%）超限跳过；接回后交给现有 `seeded>阈值` 判定，需要就留着、冗余再断开；稳定冗余走退避（10min→20min→…封顶 24h）；断开前存 path 供自动重连 | sync_guard.py + guard_webapi + 面板 |
| G9 | 调度历史扩充 | 重连/断开日志进调度历史（独立动作行 + 真实文件夹名）；50 条只数真动作（暂停/恢复/断开/重连），周期汇总行不占配额（保留「显示周期汇总」开关）；修复周期汇总截断 bug | guard_webapi + 面板 |

### 7.2 隐私约定

- **面板显示真实文件夹名**（用户本人可见）——不沿用 sync-guard 的脱敏
- **服务器端文件/日志脱敏**（guard-status.json、guard 日志只含计数与时间戳，不含文件夹标识）——脱敏针对用户以外的人（含 AI），防服务器文件/日志被第三方查看泄露

### 7.3 验收

- G1：真机验证 `/api/status` 返回 sched 数据；调度页显示真实文件夹名与分级；仪表盘徽标正确
- G2：guard 接口部署后，面板「守护」页显示核心状态
- G3：面板控制表单提交生效（切模式/调参）
- G4：服务器端部署 guard_webapi.py 后接口可用、token 认证生效
- G5：模拟/复现 OOM 风暴后安全模式触发，全部文件夹暂停且跨重启保持；稳定后自动解除、恢复常规调度

### 7.4 安全模式（2026-08-05 新增）

- **触发**：guard 检测到 NRestarts 增长（= OOM 强杀），滑窗 `RSL_SAFE_OOM_WINDOW`（默认 600s）内次数超过 `RSL_SAFE_OOM_THRESHOLD`（默认 4，即"10 分钟内超过 3 次"，2026-08-06 生产调为 3）
- **动作**：进入安全模式时直接把备份文件改写为全部 paused（保留 settings/stats）+ 恢复时强制回放全部暂停；**调度器继续运行**，按其判定恢复应运行的文件夹（非全部停摆，由调度器分批决定运行集）
- **解除**：无新 OOM 持续 `RSL_SAFE_EXIT_QUIET`（默认 1800s）后自动解除，恢复常规备份恢复 + 调度器
- **面板可改（2026-08-06）**：`safe_oom_threshold` / `safe_oom_window` / `safe_exit_quiet` 加入 guard_webapi `SCHED_KEYS` 白名单，面板「守护」页控制表单可读写；阈值最小 2、窗口/解除最小 60 秒（防误配）
- **限并发策略（2026-08-06）**：生产 OOM 根因是 rslsync 并发运行文件夹数多导致内存顶到 1.8G（87 文件夹静态索引基线 ~0.4-0.9G，运行集把内存推到 1.82G）。`RSL_SCHED_MAX_RUNNING` 由 5 调为 2，限制同时服务数、控制内存峰值；不断开任何文件夹（避免重索引）
- **实现落点**：跨 OOM 真正持久的是 guard 备份（prefs.json，原子写 + 每次重启强制回放），而非 rslsync 内存态；故不直接改 rslsync 内部 SQLite

### 7.5 冗余做种断开（2026-08-06 新增）

- **原理**：做种人数（`seeded` = 在线且 updiff=0、downdiff=0 的对端数）超过阈值说明其他对端已充分覆盖该文件夹内容，本机继续做种冗余 → 断开它节省内存（实测 ~16MB/文件夹，断开 22+ 个可释放 ~400MB）
- **触发**：guard 每备份周期（30s）检查快照，`seeded > RSL_DISCONNECT_SEEDED_MIN`（默认 10）且已连接 → `removefolder&deletedirectory=false&fromalldevices=false` 断开
- **可逆**：断开后文件夹仍在 getsyncfolders（synclevel=0），面板显示"断开连接"，可手动填路径重连
- **配置**：面板「守护」页「冗余做种断开」开关 + 阈值；env `RSL_DISCONNECT_SEEDED_ON`（0/1）/ `RSL_DISCONNECT_SEEDED_MIN`
- **实测**：生产启用后首轮断开 22 个（全为已暂停、无传输中断），rss 从 ~1.3G 降至 ~0.89G

### 7.6 仪表盘内存占用（2026-08-06 新增）

- **背景**：Resilio GUI API `getstatuses` 无内存字段，内存指标只能走服务器端 guard（本地读 /proc + cgroup）
- **数据源**：guard_webapi `GET /api/status` 新增 `mem` 字段（rss/vmswap 来自 /proc/<pid>/status；cg_current/cg_max 来自 cgroup v2；mem_total/mem_avail 来自 /proc/meminfo），面板后台抓取线程每 30s 节流采样并入 `/api/status` 载荷
- **显示**：仪表盘「内存占用」卡片，主值 = rss 占 cgroup 上限百分比（绿 <70% / 橙 70-90% / 红 ≥90% 即 OOM 高危），无上限时显示绝对值；悬停 tooltip 显示 RSS/上限/swap/系统可用明细
- **降级**：未配置 guard 或采样失败时卡片显示 "-"，不影响面板其他功能

### 7.7 断开文件夹定期重连（2026-08-06 新增）

- **背景**：G6 冗余做种断开是"一锤子买卖"，断开后失去复查机会——万一做种对端全下线、文件夹变稀缺，或本地副本落伍，都无法感知。断开后该文件夹 peer 状态过期，唯一可靠的重新评估方式是接回来观察
- **流程**：
  1. **断开前记 path**（G6 断开时）：Resilio 断开后清空文件夹 path，不记下则永远无法自动重连；记入 conn.json（600 权限、不进日志）
  2. **每 10 分钟重连 1 个**：从"已断开且到期"的文件夹里挑最久没重连的，`addsyncfolder(path, secret)` 接回（secret 从当前文件夹列表取，断开后仍在）
  3. **接回后不特殊对待**：直接交给现有 `seeded>阈值` 判定，需要就留着（成为调度器正常候选）、冗余就再断开
  4. **退避**：连续被再断开的文件夹，下次可重连时间翻倍（10min→20min→…封顶 24h），降低"已知稳定冗余"文件夹无谓的索引加载（I/O + 内存尖峰）
- **两道闸门**（任一超限，本轮跳过、下轮再试）：
  - **内存闸门**：rss / cgroup 上限 > `RSL_RECONNECT_MEM_GATE_PCT`（默认 75）→ 不重连
  - **磁盘闸门**：存储盘 IO 忙度 > `RSL_RECONNECT_IO_GATE_PCT`（默认 90）→ 不重连；忙度 = `/proc/diskstats` 差分算 %util（iostat 同义算法），`df` 自动定位存储盘
- **边界**：安全模式激活中冻结整个重连循环；调度器跳过 `synclevel==0`（服务器侧对齐面板侧）；conn.json 只跟踪 G6 自动断开，用户手动断开不受定期重连干预
- **配置**（guard env，面板「守护」页可改）：`RSL_RECONNECT_ON`（0/1）、`RSL_RECONNECT_INTERVAL`（600s）、`RSL_RECONNECT_MAX_BACKOFF`（86400s）、`RSL_RECONNECT_MEM_GATE_PCT`（75）、`RSL_RECONNECT_IO_GATE_PCT`（90）

### 7.8 调度历史扩充（2026-08-06 新增）

- **背景**：现有「调度历史」页只显示调度器的暂停/恢复动作行；重连/断开日志写在 guard 日志里但未被历史页收录；50 条配额被周期汇总行占用，真动作常被挤出；周期汇总行存在截断 bug（`line.split('] ')` 在 `调度[on] ` 的 `] ` 处二次拆分，内容被腰斩成「调度[on」）
- **内容**：
  1. **修复周期汇总截断**：仅按首个 `] `（时间戳后）拆分
  2. **重连/断开日志进历史**：断开（`冗余做种断开: fold=…`，G6 已有）、重连（新增 `定期重连: fold=…`，G8 写入）渲染为**独立动作行**：时间 + 徽标（断开/重连，与暂停/恢复区分色）+ 真实文件夹名 + 备注（seeded 数等）；分级/需上传/待下载/做种/上传速度列留空
  3. **名字映射全量**：历史页 id→真实名映射从 `/api/status` 的 `folders`（含断开文件夹）构建，当前从 `sched`（排除断开）构建导致断开文件夹显示为 id 前缀
  4. **50 条只数真动作**：暂停/恢复/断开/重连计入配额；周期汇总行**不占配额**，保留「显示周期汇总」开关（默认关）
- **历史边界**：进历史的只有逐文件夹的**重连成功**与**断开**；重连被闸门拦截、重连失败、断开批量汇总（`本轮共 N 个`）、周期汇总均不进（失败/拦截仍写 guard 日志供排障，但不带动作行标记）

### 7.9 仪表盘「定期重连」卡片（2026-08-06 新增）

- **背景**：G8 定期重连的进展此前不可见——重连了几何、还剩多少、为何暂停（IO/内存闸门）、下次何时尝试，都只能看 guard 日志。面板需要一张卡片直接呈现
- **数据源**：sync_guard 主循环写 status.json 时新增嵌套对象 `reconnect`（脱敏：只含计数与时间戳，不含文件夹 id/path）；guard_webapi `GET /api/status` 自动透传；面板后台抓取线程随 `mem` 一并节流采样（同一 30s 请求）并入 `/api/status` 载荷 `guard_reconnect` 字段
  - 字段：`on`/`interval`/`max_backoff`/`mem_gate_pct`/`io_gate_pct`（参数）、`total`（conn.json 池内条目数）、`connected`/`disconnected`（当前按 LAST_SNAPSHOT 的 synclevel 判定）、`reconnected`/`reconnect_ok_total`（累计重连成功过的条目数 / 总次数，`last_reconnect_ok` 最近一次成功时间——重连成功时在 conn.json 记 `reconnect_ok_count`/`last_reconnect_ok`，断开重建条目时保留，故跨循环单调）、`next_connect`（最早可重连时间）、`last_attempt`、`io_pct`/`io_ready`
- **显示**：仪表盘新增「定期重连」卡（摘要卡下方整行卡）：进度条 = 当前已连接 / 池内总数；徽标 = 运行中 / IO 闸门拦截中（io_pct≥io_gate_pct 变黄）/ 已关闭 / 全部已重连；明细行 = 下次尝试（倒计时/等待 IO 回落/可重连/已关闭）、最近重连（相对时间）、**IO 均值（闸门阈值）**、重连间隔。磁盘 IO 卡保持单行（Resilio `disk%`），guard IO 滚动均值改在重连卡展示
- **降级**：未配置 guard 或采样失败时重连卡隐藏（`d-none`），不影响其他功能
