# 设计规范（Design Standards）

所有代码改动必须遵守本规范。写代码前阅读，提交前对照检查。

## 1. Python 规范

### 1.1 命名与风格
- 遵循 PEP8：类名 `UpperCamelCase`，函数/变量 `snake_case`，常量 `UPPER_SNAKE_CASE`
- 使用 4 空格缩进，不使用 tab
- 行宽不超过 100 字符
- 字符串一律使用双引号

### 1.2 注释
- **默认不写注释**；只有当"为什么"不明显时才写（隐藏约束、规避特定 bug、会让人意外的行为）
- 不用注释解释"做了什么"（好的命名已说明）
- 不写大段 docstring；函数头部最多一行说明性 docstring
- 不用注释标注"新增/修复/为 X 添加"，这类信息属于提交说明

### 1.3 异常与错误处理
- 远端 API 层定义统一异常 `ResilioApiError`，调用方捕获后转为用户可读信息
- 只在系统边界（用户输入、外部 API）做校验；内部代码信任既有保证
- 不吞异常：宁可让错误上抛到统一处理处，也不 `except: pass`
- 外部请求必须有 timeout

### 1.4 安全性
- 不在日志、异常信息、返回数据中暴露密码/完整服务器地址
- 禁止将服务器密码写入任何本地文件（含 CSV）
- 所有网络参数用 `params` 传递，禁止字符串拼接 URL（防注入）

## 2. JavaScript / 前端规范

- 使用 `const`/`let`，不使用 `var`
- DOM 操作用原生 API；不引入 jQuery
- 轮询与写操作封装为独立函数，命名 `startPolling / updateDashboard / pauseFolder` 等
- 事件监听使用 `addEventListener`，不在 HTML 内联 `onclick`
- 所有 `fetch` 调用检查 `response.ok` 并处理异常，失败时给出可读提示

## 3. HTML / 模板规范

- 使用 Jinja2 模板继承（base.html 定义布局与导航）
- 文案使用中文（与项目语言一致）
- 表单输入做前端校验（数值范围、必填）
- ID/类名使用语义化命名（如 `folder-row`、`download-speed`）

## 4. 日志规范

- 本地 Flask 日志：记录请求级别信息（时间、端点、耗时、结果），**不记录凭据**
- 远端 API 错误：记录 action、HTTP 状态、错误码；不记录响应全文
- 开发过程记录以提交说明（commit message）为准

### 4.1 隐私边界（sync-guard 集成，2026-08-05）

- **面板是给用户本人看的，显示真实文件夹名**（调度页、仪表盘、调度历史、以及任何涉及具体文件夹的状态/动作）——不沿用 sync-guard 的脱敏
- **服务器端文件/日志脱敏**（guard-status.json、guard 日志只含计数与时间戳，不含文件夹 name/path/peer 标识）——脱敏针对用户以外的人（含 AI），防服务器文件/日志被第三方查看泄露
- **conn.json（G8 定期重连，2026-08-06）**：记录 G6 断开文件夹的服务器本地 path，**路径末段≈文件夹名**，属"备份文件级"敏感数据——与 prefs.json 同级对待：600 权限、只存服务器本地、**绝不进日志**；日志只记 fold 前缀 + 计数
- 写面板侧代码时，任何来自服务器端的 guard 数据按上述边界处理：能显示真实名的（面板展示）就显示，服务器端落盘/落日志的保持脱敏

### 4.2 调度历史日志格式（2026-08-06 新增）

guard 日志中供「调度历史」页消费的行，按标记分动作行与汇总行（read_history 与前端按此识别）：

```
动作行（计入历史 50 条配额）：
  调度器暂停/恢复  调度[模式] 周期#N fold=<id前8> C<级> need=.. dneed=.. seed=.. up=..KB 动作=暂停|恢复
  断开            冗余做种断开: fold=<id前8> seeded=..>..
  重连            定期重连: fold=<id前8> 已重连        （G8 新增）
汇总行（不计配额，可开关显示）：
  周期#N 文件夹=.. 运行=.. C=.. D=.. 变更=..(暂停.. 恢复..) 耗时..ms 模式=..
```

约束：
- 动作行必须含 `fold=` 且可被历史页识别；**批量汇总（`本轮共 N 个`）与失败/拦截日志不含动作行标记**，不进历史但可写日志排障
- 重连日志只写成功（`定期重连: fold=`），失败/闸门拦截用不带该标记的措辞（如 `定期重连失败 fold=…`）
- 全部日志脱敏：只含 id 前缀与计数，不含文件夹 name/path/secret

## 5. 测试与验证规范

- **每阶段完成即验证**，验证通过才进入下一阶段（见 development-plan.md）
- 改动 API 客户端（resilio_api.py）后必须回归验证核心流程
- API 客户端新增方法先用独立脚本连接真实远端冒烟测试
- 前端改动在浏览器实测（启动 Flask 后用浏览器访问验证），不能只凭类型/语法检查通过就宣称完成
- 提交前检查：无残留调试输出、无未使用导入、无死代码

## 6. 变更纪律

- 一次只做一个阶段的工作，不顺手重构无关代码
- 新功能必须同步更新对应的 docs 文档（需求变更则更新 requirements.md）
- 每周对照 development-plan.md 检查进度，偏差及时记录
